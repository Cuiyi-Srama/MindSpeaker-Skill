# MindSpeaker-Skill

> 先说清是谁在说，再谈怎么写。

一套写作 skill。写之前把人定下来，写的时候守住规矩，写完自己验一遍。

中文英文都能用——它判断的是人，不是语言。

---

## 它能干什么

十件事，每件都能单独拿出来干：

| # | 能力 | 产出 | 在哪 |
|---|---|---|---|
| 1 | **逼出说话人**：谁在说、为什么想说、讲到哪会停、说话什么毛病。四题填通用词就打回重填 | 说话人档案 | `00` 第一节 |
| 2 | **逼素材**：具体的设备动作、一段翻车过程、观察者的反应。缺一类就停，不许编 | 素材清单 + 缺口清单 | `00` 第二节 |
| 3 | **画情绪线**：先排情绪再写，不按信息分类排 | 情绪节点顺序 | `00` 第三节 |
| 4 | **拦住"演"**：加问号的排比、点缀式语气词、刻意碎片句——这几样是人为加上去的假活人 | 命中清单 | `00` 第四节 |
| 5 | **三重检验**：谁在说 / 哪句在替读者鼓掌 / 哪句念出来端着。标准是耳朵 | 通过或不通过的句子 | `00` 第五节 |
| 6 | **救空稿**：诊断空洞 → 判观点死活 → 拆骨架重搭 | 重写稿 | `03-场景A` |
| 7 | **写长文**：逐段问"这一段素材够吗"，不问"意图是什么" | 分段稿 + 素材状态表 | `04-场景D` |
| 8 | **风格建模**：角色定下来之后的分支。过程可交给成熟工具，也有手机轻量版；产出落 `styles/` 可持续迭代 | 风格模型文件 | `05-场景C` |
| 9 | **轻清洗**：只改说法，结构一字不动 | 干净稿 | `06-场景E` |
| 10 | **口播稿**：从审问到成稿的主模式 | 能念的稿 | `02-场景B` |

## 两种用法

它是完整的，也是零散的。整套能跑，单件也能用。

### 当整条流程用

从零写一篇口播稿、长文，或者救一篇读着空的 AI 稿：

| 步 | 做什么 | 产出 |
|---|---|---|
| 1 | 人物审问四题 | 说话人档案 |
| 2 | 素材逼问三类 | 素材清单 + 缺口清单 |
| 3 | 画情绪线 | 情绪顺序 |
| 4 | 写初稿 | 初稿 |
| 5 | 清洗 | 干净稿 |
| 6 | 三重检验 | 检验结果 |
| 7 | 交付 | 稿子 + 缺口说明 + 检验结果 |

**顺序不能倒。** 先清洗再补人物，等于给空话换包装。

### 单点调用

只有一个具体麻烦时，直接翻对应那节，不必跑完整流程：

| 你的麻烦 | 读哪节 |
|---|---|
| 不知道这篇该由谁来说 | `00` 第一节 · 人物审问 |
| 稿子读着空，说不出缺什么 | `00` 第二节 · 素材三类 |
| 素材一堆，不知道怎么排 | `00` 第三节 · 情绪线 |
| 总觉得写得"演" | `00` 第四节 · 反伪活人 |
| 写完了，念着不对劲 | `00` 第五节 · 三重检验 |
| 有篇 AI 稿想救活 | `03-场景A` |
| 长文写一段崩一段 | `04-场景D` |
| 想照着某人的文风写 | `05-场景C` |
| 只想改说法，结构别动 | `06-场景E` |

## 它不管什么

- 不判断文本是不是 AI 写的，也不保证通过任何检测器。
- 不替作者编素材。这条没有例外，是全部内容里唯一的硬红线。
- 不硬凑字数。素材不够就停下来问，问不出就写短。

---

## 几条常见误会

**"它只是个调度壳子吧？"** 不是。人物审问、素材逼问、情绪线、反伪活人、三重检验、风格建模的判据都在 `00` 和 `05` 里，是这套东西自己的。清洗规则才是借来的。

**"风格建模不是它的活吗？"** 是。`05` 里给了七项指标和数法，也写了三条边界。手上若已有专门做这件事的 skill，直接用它的产出也行。

**"英文怎么办？"** 照用。审问、素材、情绪线、检验、风格建模都不分语言。只有字面清洗这一层，中文有内置规则，英文需要另装一份（见文末）。

**部署自检**：让它做一次人物审问，比如「按 MindSpeaker-Skill 给这篇稿子做人物审问」。能交出四题的具体答案，说明装好了；如果它直接开始改稿，说明只读了 `SKILL.md`、没读 `00`。

## 走一遍（压缩版）

**① 人物审问**
> 谁在说：一个自己试了这玩意、被惊到、又踩了坑的玩家
> 为什么想说：我看到关网还能玩的时候第一反应是不对劲
> 讲到哪会停：懒得升华，讲完兼容性就想收
> 说话毛病：爱用短句砸、爱自问自答、翻车时话变碎

**② 素材**
> 设备：A 设备，下了某游戏，Wi-Fi 关、移动数据关
> 翻车：点启动、黑屏、等半分钟、退
> 反应：第一反应是"这不对吧"

**③ 情绪线**
> 不信 → 离谱 → 无奈 → 认了 → 忍不住想说 → 收
> （每次重画。照抄形状就是新模板。）

**④ 写**
> 素材原话优先于漂亮句子；不表演口语；写不出来就停。

**⑤ 清洗**
> 按 `vendor/humanizer-zh` 的规则过一遍，交代「保留事实、数字、引语、语气强度」。

**⑥ 检验**
> 念一遍。某段换个人来说还成立 → 那段漂了，退回改。

**⑦ 交付**
> 稿子 + 素材缺口说明 + 检验结果。

## 设计原则

1. **素材 > 人物状态 > 风格卡 > 字面规则。** 顺序倒了，技巧就会盖住人。
2. **不编细节。** 缺素材是停下问，不是补一个像样的。这条高于一切技巧。
3. **只报命中，不给替换句。** 替换句一给，这套东西就变成新模板生成器。
4. **警报不是刑具。** 命中只意味着停一下看一眼，判断权在写的人。
5. **反伪活人。** 所有"活人句式"都是事后总结，不是事前模板。不建模板库。
6. **一次一稿。** 下一篇从审问重新开始。
7. **能借就借。** 现成规则直接拿来用，不自己重写一遍。
8. **能不用就不用。** 用几次之后，动笔前会自然先问"谁在说"。到那时这套东西就该放下。

## 风格建模的来历

`05` 里那张表（九项指标）是本项目自建的，骨架来自这套东西最初的设计大纲。对照公开实现后补了两项——**态度**（评价直接还是先铺垫、怎么夸人怎么认错）和**高频词频次**——来自 `jack-reson8/renhua`（MIT），它是从 407 句真实原话统计出「节奏／态度／常用词／专业词／数字」五类的。

同类工具里，`fengin/umani`（MIT，余香）做的是同一件事：从修改 diff 反复迭代出写作 skill。但它是 Tauri 桌面应用，得在电脑上跑，手机端带不动，所以只参考思路，没有内置。`liam-page-writing`、`style-mimic` 未能核实到可达路径，不使用。

**建模过程可以整个包出去**，本项目不参与。它负责的是另外两件事：决定这个角色要不要建模，以及把建模结果按统一格式落进 `styles/`——一份角色一份文件，带样本量、统计日期、精度等级和变更记录，可以一直迭代下去。手机端用九项指标手工数一遍，也能出一份"粗"精度模型，够日常写稿用。

## 内置的清洗规则

`vendor/` 下三份中文清洗规则，开箱即用：

| 规则 | 特点 |
|---|---|
| [Humanizer-zh](https://github.com/op7418/Humanizer-zh) | 31 条判据，覆盖铺垫、节奏、拔高、排版、中文特有毛病 |
| [qu-ai-wei](https://github.com/LifelongLazyLearner/qu-ai-wei) | 规则打架时按它的仲裁顺序；有普通/内嵌两种模式 |
| [说人话 shuorenhua](https://github.com/MrGeDiao/shuorenhua) | 先锁事实再动语气，职场稿最稳，也能只标不改 |

三份都是 MIT，各自目录里有 LICENSE。唯一改动是给它们的 `description` 加了个前缀，让它们不单独抢触发——所以要用就读文件：**读 `vendor/humanizer-zh/SKILL.md`，按它的规则处理本稿**。

英文清洗另装：`de-ai-ify` 或 `blader/humanizer`，未内置，许可自行核对。

## 已知问题

- **触发词竞争**：本地若还装着别的去 AI 味 skill，可能被它们截胡。停用旧的（改名加前缀）或移出 skills 目录即可。
- **依赖按路径读文件**：只加载 `SKILL.md`、读不到同目录文件的环境，拿到的只有骨架。按上面的自检跑一次就知道。
- **数字型判据需要语感**：比如"连续三段都以短句收尾"，边界靠人判断，不靠计数。
