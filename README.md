# mindspeaker

> 先说清是谁在说，再谈怎么写。

一套写作 skill。既能当整条流程跑（从素材到成稿），也能当一堆小工具单点调用（只审问人物、只画情绪线、只查某类句子）。

中文为主，英文稿有单独一档。

---

## 名字

`mind` + `speaker`。

不叫「去 AI 味工具」，因为它主要不在文字表面动手。它管的是文字背后那个人：谁在说、他为什么想说、讲到哪会停、他说话有什么毛病。

市面上不缺擦字的工具。缺的是动笔之前那个人。

---

## 它填哪个空

现有的去 AI 味 skill 基本落在三类：

| 类别 | 管什么 | 代表 |
|---|---|---|
| 清洗类 | 稿子写完之后删掉什么 | Humanizer-zh、qu-ai-wei、说人话、lieflat-less-ai-tone |
| 风格建模类 | 像谁写的 | umani、renhua、liam-page-writing |
| 逐段协作类 | 一段一段来 | rui-writer |

三类都在处理**稿子**。没有一类在动笔前逼出一个具体的说话人状态。

rui-writer 最接近，但它审的是段落意图（「这一段你想表达什么」），不是人的状态。逐段流程里填一个通用意图，结构对了，里面还是没有人。

所以这套东西的位置是：**稿子之前**。清洗它不做，交给上游；上游不管的那一层它兜住。

---

## 两种用法

这是它和多数 skill 不一样的地方：**它不是只能整套跑的流程，也不只是一堆散件。** 每个环节单独拿出来都有产出。

### 用法一 · 当整条流程用（全面）

适合：从零写一篇口播稿、长文，或者救一篇读着空的 AI 稿。

| 步 | 做什么 | 谁干 | 产出 |
|---|---|---|---|
| 1 | 人物审问四题 | 本 skill | 一份说话人档案 |
| 2 | 素材逼问三类 | 本 skill | 素材清单 + 缺口清单 |
| 3 | 画情绪线 | 本 skill | 情绪节点顺序 |
| 4 | 写初稿 | 本 skill 守铁律 | 初稿 |
| 5 | 字面清洗 | `vendor/` 上游 | 干净稿 |
| 6 | 三重检验 | 本 skill | 通过 / 不通过的句子清单 |
| 7 | 交付 | — | 稿子 + 缺口说明 + 检验结果 |

**顺序不能倒。** 先清洗再补人物，等于给空话换包装。

### 用法二 · 单点调用（点状）

适合：你只有一个具体的麻烦，不需要走整条流程。

| 你的麻烦 | 读哪一节 | 拿到什么 |
|---|---|---|
| 不知道这篇该由谁来说 | `00` 第一节 · 人物审问四题 | 说话人档案，四题全须是具体的话 |
| 稿子读着空，说不出缺什么 | `00` 第二节 · 素材三类 | 缺哪一类、要问作者什么 |
| 素材一堆，不知道怎么排 | `00` 第三节 · 情绪线 | 情绪节点顺序 + 两处检查 |
| 总觉得自己写得「演」 | `00` 第四节 · 反伪活人四条 | 四条判据，专治表演型口语 |
| 稿子写完了，念着不对劲 | `00` 第五节 · 三重检验 | 哪句漂了、哪句在替读者鼓掌、哪句端着 |
| 有篇 AI 稿想救活 | `03-场景A` | 诊断 + 死活判断 + 重搭步骤 |
| 只想把说法改掉，结构别动 | `06-场景E` | 选哪个上游 + 调用话术 |
| 想照着某人的文风写 | `05-场景C` | 风格卡七项 + 三条边界 |
| 长文写一段崩一段 | `04-场景D` | 逐段确认素材的跑法 |

单点用法不要求先跑完整流程。每节都能独立读、独立产出。

### 两条用法共用的四条自建判据

上游没有、由本 skill 兜住的四条（代号 G1–G4，详见 `01` 第五节）：

- **G1 表演型口语**：加问号的排比、点缀式语气词、刻意的碎片句。清洗类是在删 AI 痕迹，这一类是**人为加上去的假活人**，方向相反，它们清单里没有。
- **G2 段长方差裁决**：不许为了制造参差去调句长、拆段落。有的 skill 会建议打散整齐结构，这条反过来管住它。
- **G3 说话人视角检验**：某一段换任何一个人来说都成立，那段就是漂的。上游只判句子，不判这句是谁在说。
- **G4 素材缺口声明**：哪几处因为没料而没写，交付时说清楚。上游会免责，不会向作者要料。

G1 和 G2 互相牵制：一个管「别为了像人而演」，一个管「别为了不像 AI 而打散」。两条同时在，稿子才不会改出第三种种假。

---

## 它不做什么

- 不做字面清洗细则。上游有 31 条、八族扫描，比这里全。要清洗直接读 `vendor/`。
- 不做风格建模方法。那是 umani / renhua / liam-page-writing 的活。
- 不判断文本是不是 AI 写的，也不保证通过任何检测器。
- 不替作者编素材。这条没有例外。

## 部署

跟 AI 说一句「帮我部署 mindspeaker」，或者手动：

```bash
git clone https://github.com/Cuiyi-Srama/mindspeaker.git
```

把它放进你的 skills 目录：

| 环境 | 路径 |
|---|---|
| Operit | `/sdcard/Download/Operit/skills/mindspeaker/` |
| Claude Code / 兼容 skill 目录 | `~/.claude/skills/mindspeaker/` |
| 其他 | 认 `SKILL.md` 的任意 skills 目录 |

**部署后自检**：让它做一次人物审问，比如「按 mindspeaker 给这篇稿子做人物审问」。能交出四题的具体答案，就算装好了；如果它直接开始改稿，说明只读了 SKILL.md、没读 `00`。

## 走一遍（压缩版）

想看每一步的产出长什么样：

**① 人物审问**
> 谁在说：一个自己试了这玩意、被惊到、又踩了坑的玩家
> 为什么想说：我看到关网还能玩的时候第一反应是不对劲
> 讲到哪会停：懒得升华，讲完兼容性就想收
> 说话毛病：爱用短句砸、爱自问自答、翻车时话变碎

**② 素材逼问**
> 设备：A 设备，下了某游戏，Wi-Fi 关、移动数据关
> 翻车：点启动、黑屏、等半分钟、退
> 反应：第一反应是「这不对吧」

**③ 情绪线**
> 不信 → 离谱 → 无奈 → 认了 → 忍不住想说 → 收
> （每次重画。照抄形状就是新模板。）

**④ 写**
> 守三条：素材原话优先于漂亮句子；不表演口语；写不出来就停。

**⑤ 清洗**
> 读 `vendor/humanizer-zh/SKILL.md`，交代「保留事实、数字、引语、语气强度」。

**⑥ 三重检验**
> 念一遍。某段换个人来说还成立 → 那段漂了，退回改。

**⑦ 交付**
> 稿子 + 素材缺口说明 + 检验结果。

## 设计原则

1. **素材 > 人物状态 > 风格卡 > 字面检测项。** 顺序倒了，技巧就会盖住人。
2. **AI 不许自造细节。** 缺素材是停下问，不是补一个像样的。这条高于一切技巧。
3. **标记环节只报命中，不给替换句。** 替换句一给，这套东西就变成新模板生成器。
4. **警报不是刑具。** 命中只意味着停一下看一眼，判断权在写的人。
5. **反伪活人。** 所有「活人句式」都是事后总结，不是事前模板。不建模板库。
6. **一次一稿。** 下一篇从审问重新开始。
7. **不重复造轮子。** 上游有成熟实现的，一律委派，只写调用关系与缺口。
8. **能不用就不用。** 用几次之后，动笔前会自然先问「谁在说」。到那时这套东西就该被放下。

## 与上游的关系

| 上游 | 提供什么 | 许可 |
|---|---|---|
| [Humanizer-zh](https://github.com/op7418/Humanizer-zh) | 31 条中文清洗判据（铺垫代替陈述、公式化节奏、拔高借权威、排版、聊天残留、中文补充检查） | MIT |
| [qu-ai-wei](https://github.com/LifelongLazyLearner/qu-ai-wei) | 规则仲裁顺序、八族扫描、冻结不可丢失内容、普通／内嵌双模式 | MIT |
| [说人话 shuorenhua](https://github.com/MrGeDiao/shuorenhua) | 先锁事实再动语气；可只标问题不改 | MIT |

内置在 `vendor/`，各带 LICENSE。

**对上游做过的唯一改动**：给 `description` 加了前缀 `[vendor·供 mindspeaker 调用，不独立触发]`，关掉独立触发，避免与主 skill 抢触发词。正文一字未改，文件头有注释说明。

**因此必须按路径调用**：「读 `vendor/humanizer-zh/SKILL.md`，按它的规则处理本稿」。写成「调用 humanizer-zh skill」会找不到，它已经不是一个可独立唤醒的 skill。

## 已知问题

- **触发词竞争**：本地若同时装了别的去 AI 味 skill，仍可能被它们截胡。正解是把旧的那几份停用（改名加前缀）或移出 skills 目录。
- **依赖按路径读文件**：某些运行环境只加载 `SKILL.md`、读不到同目录文件。那样只能拿到骨架，人物审问的具体判据会丢。部署后按上面的自检跑一次就知道。
- **未核实的上游**：`blader/humanizer`、`no-ai-slop`、`human-writing`、`umani`、`renhua`、`liam-page-writing`、`style-mimic`、`rui-writer` 在编写本仓库时未逐一核实到可用仓库路径，因此没有内置。要用请先自行确认地址与许可证。
- **中文为主**：英文只有 `06-场景E` 里的一档提示，没有独立流程。
